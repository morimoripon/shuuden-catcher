# ADR-0003: 経路データは ODPT から取り、Google の経路 API と有料の乗換 API は使わない

- **Status**: Accepted
- **Date**: 2026-10-07（判断自体は 2026-10 の競合調査時。本 ADR で追認記録）
- **関連**: ADR-0001（API キーなしで動くサンプルデータのモード） / ADR-0002（時刻表をリポジトリにコミットしない）

## 背景（Context）

終電を計算するには、駅・路線・時刻表のデータか、経路を返してくれる外部 API が要る。

制約は次のとおり。ソロ開発のポートフォリオで収益は無く、運用費はできるだけ掛けない。
GitHub で公開し、clone した人が手元で動かせる形にしたい。全国を網羅する必要は無い。

2026-10 時点で、候補になるデータ源は次の 3 系統だった。

- Google の経路 API（Routes API / Directions API）
- 有料の乗換 API（駅すぱあと・NAVITIME）
- 公共交通オープンデータセンター（ODPT）の GTFS / API

## 決定（Decision）

1. **経路データは ODPT の GTFS / API から取る。** batch が取得・前処理し、終電の計算は自前の core で行う（ADR-0001）
2. **対応エリアは、首都圏の ODPT 対応路線に限る。** 対応していない路線・事業者があることは README に明記する
3. **時刻表はリポジトリにコミットしない。** ODPT の利用規約上、再配布できない可能性があるため、batch で都度取得する（ADR-0002）

## 代替案（Alternatives）

- **Google Routes API / Directions API**: 日本の公共交通の経路に対応しておらず、`travelMode: TRANSIT` で日本の駅間を引くと `ZERO_RESULTS` が返る。終電の計算に使えないので却下。
- **駅すぱあと・NAVITIME の API**: 経路探索の精度と対応範囲は申し分ない。ただ有料で、収益の無いプロジェクトではコストだけが掛かる。clone した人も各自で契約しないと動かせず、公開リポジトリとして試してもらえないので却下。

## 結果・影響（Consequences）

- 経路データの費用は掛からない。ODPT は開発者登録（無料）でアクセストークンを取る必要があるが、トークンが無い人にはサンプルデータのモードで動かしてもらう（ADR-0001）
- 終電の計算（逆向き RAPTOR / CSA）を自前で書くことになる。乗換の最小時間や日付をまたぐ時刻など、乗換 API が吸収してくれていた部分を core で扱う
- 首都圏でも ODPT に時刻表が無い路線・事業者は対象外になる。どこまで揃うかは core の検証で確かめる
- **着手前に確かめること**: ODPT の利用規約で、時刻表から計算した終電を自前の API・アプリから配信してよいか。配信できない場合は、本 ADR と ADR-0002 を前提から見直す
- 見直し条件: Google の経路 API が日本の公共交通に対応した場合、あるいは対応エリアを ODPT の外へ広げる必要が出た場合
